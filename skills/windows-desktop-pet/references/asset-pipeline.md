# 动作素材流程

## 角色与生成

先固定角色参考：脸部花纹、耳形、腿长、尾巴、前后与左右视角。已有角色由用户选择，不为让生成更容易而改成另一种风格。多个参考冲突时确认基准，避免每段“同一只狗”实际长相不同。

提示词要同时描述动作与可连接的端点。可以按下列结构写；帧率、时长、背景是项目参数，不是所有模型都支持的保证。

```text
以所提供角色参考为准，保持脸部花纹、四肢比例、耳朵和尾巴一致。
固定机位、固定焦距，全身在画面内，四周保留动作余量。
起点：[明确姿态、朝向、大小、地面线]。
过程：[一个完整动作，写清承重、抬脚、落脚和身体跟随关系]。
终点：[明确姿态]，短暂停稳，以便接到下一段。
背景：[适合该角色分离的均匀背景]；没有文字、水印和额外物体。
避免镜头推拉、突然换姿势、滑步、截断耳朵尾巴和额外肢体。
```

左右转身要描述头、肩、躯干、后腿依次跟随，以及脚部重新承重，不能只写“向左走”。独立生成左转、左回正面、右转、右回正面便于补错；如果用户只要一段连续表演，也可先生成完整视频，再按实际可用帧拆段。不要强迫用户遵循固定素材数量。

行走、敲键盘这类持续活动通常拆为进入、正向循环、收尾。先测一侧的完整路线，再制作更多变体。镜像只在花纹和方向要求允许时使用，不能自动把另一侧素材替换成镜像。

## 接收与检查

登记文件实际存在位置、编码、宽高、fps、时长、帧数、有无 alpha、对应角色／版本。根据文件名提出状态判断后，还要看首、中、尾帧；文件名不是画面事实。

- 白底 MP4：边缘背景估计与连通区域可作为简单场景起点，保留主体内白毛。白毛直接连到白背景、毛发很细或背景复杂时，需更合适的主体分割、人工修正或重新导出，不能认为填充轮廓总能解决。
- 透明 MOV：实际解码 RGBA，检查 alpha 是否既含透明又含主体；播放时黑底／白底预览不等于 alpha 丢失。已有透明素材优先保留，避免重复抠像损伤毛发。
- PNG 序列：检查排序、缺号、尺寸、帧率来源和透明方式。PNG 文件本身不会记录整段播放 fps。
- 声称 60 fps 的导出需分辨真实运动采样、插值与重复帧。30 fps 素材在 60 Hz 窗口绘制不等于新增了运动细节。

保护用户确认的描边、特效、人手和道具。先区分原片已有截边与运行窗口裁切：缺失的尾巴不能靠放大画布恢复。

## 尺度、脚底与循环

对同姿态参考测量主体高度、躯干宽度和地面接触点。站、坐、趴不强制等高；人手、键盘、特效不能混进小狗尺寸测量。用稳健躯干或人工基准约束整段变换，避免每帧追踪包围框造成呼吸式缩放。

区分三类坐标：源画布、运行透明缓冲、桌面窗口。裁掉透明空白是存储优化时，保留 crop_rect、原 canvas_size 和贴回偏移，恢复后应与原全画布像素一致；不要顺手裁掉内容。

独立动作接点可按脚底注册。同一连续场景拆出的进入／循环／退出沿用同一坐标，不能因步态换支撑脚或键盘进入而每段重新定位。扩大透明缓冲时反向补偿窗口位置，保证小狗屏幕坐标与拖动抓取点连续。

检查循环的第一帧与最后一帧：位置、姿态、速度、方向都要接得上。倒放不自动等于自然返回；眨眼、踩地、起身和道具动作尤其需要人工观看。短融合会有重影，应在实际显示尺寸下检查，不能把融合当作所有跳变的修复。

每批先出透明棋盘格预览、深浅背景预览及首中尾接触表。发现主体漂移或缺图时，先判断应该修代码还是补素材，再决定批量处理。

## 动作表与检查器

生产清单建议保留：ID、来源、起止状态、动作类别、方向、fps、帧范围、锚点、循环方式、使用目的。以下是独立检查器的最小格式；`path`、`fps` 和 `frame_count` 均可省略，`routes` 可只写本次需要验证的路线。

```json
{
  "initial_state": "stand_front",
  "actions": [
    {"asset_id": "idle", "start_state": "stand_front", "end_state": "stand_front", "kind": "loop", "path": "frames/idle", "fps": 30, "frame_count": 120},
    {"asset_id": "sit_down", "start_state": "stand_front", "end_state": "sit_front", "kind": "transition"},
    {"asset_id": "rise", "start_state": "sit_front", "end_state": "stand_front", "kind": "transition"}
  ],
  "routes": [
    {"name": "sit-and-return", "start_state": "stand_front", "actions": ["idle", "sit_down", "rise"], "end_state": "stand_front"}
  ]
}
```

`kind` 只取 `loop`、`transition`、`effect`。一个实际支持反放的片段，应以独立 action ID 登记正确的反放起止状态，检查器不会推测倒放是否合法。派生待机也须有独立 ID，不虚构新的来源视频编号。

检查器默认检查结构、声明的路线，并报告从 initial_state 不可达的动作为警告；不枚举所有可能命令，也不检查每个状态的返回路径。`--check-files` 检查声明的 path 是否存在；`--portable` 拒绝绝对路径和逃出清单目录的路径。诊断映射用于检查包内资源时，应放在与路径相符的包目录中，避免把检查文件位置当成丢资源。
