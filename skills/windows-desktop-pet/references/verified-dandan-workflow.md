# 诞诞案例：复现哪些已验证做法

本技能以已完成的诞诞桌宠为例，但把“历史上确实做过”和“为了让别人复现而新增的规划规范”分开。原始聊天和私人路径不随仓库公开。

## 可核对的流程

- 用宠物照片约束同一角色；早期独立图片动画存在步态／体型漂移，后来转向连续 AI 视频。
- 原实施从 16 条白底 MP4 开始，之后用户提供剪映智能抠像导出的 alpha MOV；程序解码为 RGBA 序列，而不是要求用户必须导出 PNG。实际新增视频为 30 fps，早期提出的 60 fps 不是最终交付事实。
- 基础姿态主干为正面站立→坐姿→抬头趴姿→枕爪。处理程序先建立站姿基准，再依次使用转换尾姿态对齐坐、趴、枕爪。
- 早期部分返回使用倒放。后期新增自然抬头、趴转坐、坐转站，替换对应旧倒放；不能把“所有返回都倒放”当成最终正确流程。
- 打字和左右走路各有完整连续来源视频，再拆出进入、循环、退出，共用场景坐标。切点来自实际素材，不是所有视频通用的固定帧号。
- 规划转身时，用户指出提示词只生成了左右走、没有转身，于是补出正面向左／右转身以及两侧回正面的独立提示词。这是“复杂整段生成不稳定时再拆”的直接依据。
- 最终程序含 40 个来源动作、57 个播放片段，支持姿态、摸头、拖动走路、键盘联动、自由活动和正常出入场。来源数与派生片段数分开计数。

源码例子在本仓库 `examples/dandan`；完整 Windows 示例及实际运行素材通过 Release 提供。源程序通过了基础路线、取消、恢复和自由活动等检查；这些不替代新宠物素材的视觉验收。

## 新技能补上的部分

为陌生 agent 明确写出每个动作的参考图来源、静态／动态配对卡、待生成依赖、合格尾帧升级规则、角色漂移回退和分批生产顺序，是本次把经验转换为流程的工作。

这些规则吸收了实际问题与修复，不宣称原项目从一开始就完全按这套表制作，也不宣称已在其他生成平台完成整只新宠物的端到端制作。独立试走验证的是 agent 能否据此给出完整、连贯的规划；真实生成和另一台电脑运行分别需要后续实际验证。
