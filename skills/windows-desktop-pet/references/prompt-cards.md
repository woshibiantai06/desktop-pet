# 静态图、动态视频与交接卡

## 每个动作的必填卡片

将以下结构写成用户能直接照做的内容。括号内容是编写要求；实际交付必须换成项目专属内容，不能保留变量。

```text
动作 ID 与名称：
用途、制作阶段、起点状态 → 终点状态：
前置依赖：
输入图片：逐张写明身份参考、首帧、尾帧目标的不同角色。
静态处理：新生成／复用认可图／提取上段合格帧。
静态图片提示词：如本步不需要生成，明确“备用，不执行”，仍给备用提示词或链接对应已交付的完整标准图卡。
动态视频提示词：完整可复制正文。
负面约束：针对本动作，不与允许的手、道具、姿态变化冲突。
建议时长与画面要求：属于目标，不伪称工具已保证。
结束后保存：视频名、实际尾帧名及待回填的时间戳／帧号。
尾帧去向：建立哪个状态基准、供哪条动作作首帧；或明确不传递、继续用原基准。
循环／拆段方式：同源进入、正向循环、退出；切点待实际检查。
验收：身份、肢体、尺度、脚底、首尾、循环相位。
失败处理：改哪一段／提示词，哪些下游等待或需要重做。
下一步：一个可以执行的具体动作。
```

## 标准图提示词如何编写

标准图的任务是固定身份和几何，不是做海报。写清：真实照片确认的特征、照片之间的用途、一个姿态、一个视角、全身留白、地面线、统一光照与背景；不加入身份照片里无依据的花纹。

例如写实棕白小狗的正面站姿可以展开为：

> 使用我上传的宠物照片作为同一只小狗的身份参考。保留照片中棕色头部与背部、额头到鼻梁的白色纵纹、白色口鼻和胸前毛发、自然下垂的耳朵、黑棕色鼻头及照片可见的腿长比例。生成一张固定机位的标准正面全身站姿参考图。头和身体正对镜头，四脚自然承重，耳朵与尾巴完整入画；采用正常透视，不延续俯拍的大头短腿效果。画面只保留这只小狗，均匀纯色背景，柔和稳定光照，身体位于画面中央，地面线接近画布底部并留足余量。保持真实毛发和自然动物比例，不加入人物、家具、项圈、文字或额外物体。照片未展示的背侧花纹不要当作已确认特征。

这只是格式示例，新的宠物要替换全部身份描述，不能把棕白小狗特征套到别的宠物上。

## 动态提示词如何编写

每段视频都应包含：输入图角色、首姿态、动作的物理过程、尾姿态与停稳、同一角色约束、固定机位、全身余量、背景与道具规则。转身写出头部引导、肩背跟随、脚部调整、最终站稳；起身写出爪支撑与前后躯承重，不能只写“平滑转换”。

同姿态循环要写“保持姿态与原地位置，动作结束恢复可衔接的相同姿势”；需要移动时区分素材中的原地步态与程序的桌面平移。模型不一定严格闭环，必须事后看实际尾帧和速度。

时长按实际动作复杂度安排：简单小动作可较短，多段键盘表演需要更长，若平台不足便拆段。不要承诺一个固定秒数一定能容纳任意动作。

## 用户收到的文档

可采用四份文件或一份完整文档，顺序要连贯：

1. **角色与标准图**：照片表、确认／未知特征、统一参数、静态提示词、参考图状态。
2. **动作和配对提示词**：动作总表、所选范围全部卡片、状态图。
3. **生成顺序与交接表**：依赖、输入图、生成／提取、尾帧用途、保存名、验收、返工及下一步。
4. **素材验收与程序交接**：已选导出路线、素材命名／状态清单、待实现互动与验证范围。

规划中的未来帧和视频都用“计划／待生成／待验收”标记。只有真的读取成片并检查后才能写“通过”。用户只需按卡片做，不应再根据抽象原则自己推导接哪张图。
