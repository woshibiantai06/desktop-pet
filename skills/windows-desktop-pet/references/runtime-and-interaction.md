# 播放器与互动

## 状态和队列

动作满足 `current_state == clip.start_state` 才可开始，正常结束后更新为 end_state。状态至少区分姿态和朝向；远近视图、带键盘的专用姿态也可能需要独立状态。不能只因二者都“正面”便直接相接。

新目标从实际姿态规划合法路线。相同目标重复到达时合并请求，方向抖动可做阈值／滞回；模式切换清理尚未执行的旧目标，并保留需要自然收尾的当前动作。完成标记、循环次数与实际帧位置要区分。

交互优先级要根据用户选择定义。诞诞的经验是退出及时接管、明确姿态覆盖旧任务、打字／拖动优先于未开始的随机动作；这不是所有桌宠都必须照抄的优先级。自由活动是用户可切换的模式，不应默认屏蔽用户需要的互动。

任何安全接管点都需检查暂停与恢复语义：动画在等待拖动阈值时暂停，接管分支必须恢复，否则会永久等待完成。倒放应从当前帧开始，不从整段末尾跳回；终止帧只停留一次，避免正反方向切换额外卡一帧。

## 具体互动

**拖动与改向：** 鼠标抓取点、桌面位置与步态分开管理。达到方向阈值才切行走目标；改向先完成必要转身，不立刻翻面。松开后收步并回到合法姿态。用户只想搬位置的模式可保持原动作，不必播放走路。

**头部互动：** 用显示变换后的头部范围判断点击。站、坐、趴分别路由；若有站姿摸头素材就直接使用，不为复用坐姿素材先坐下。保留用户确认的互动人手。

**鼠标注视：** 方向图使用一致的角色基准，进出注视沿合法锚点衔接。诞诞 WPF 分支用 cursor_gaze 九宫格，并按当前朝向镜像索引；不要在多套轮廓不同的正面／侧面图片间频繁硬切。

**键盘联动：** 仅为触发动作时可读取聚合活跃信号，不记录用户输入内容。分开“准备打字”“正在循环”“停止收尾”：准备途中停止输入，取消未开始的后续步骤，完成当前短段；恢复输入从当前真实姿态继续。输入宽限时间属于交互参数，不照搬历史秒数。

**自由活动：** 开关、按钮文字和选中状态同步；明确哪些触发被屏蔽，哪些操作始终可用。开启时已在打字／走路应正常收尾；取消模式不强制瞬间站立，也不覆盖用户此前的键盘开关偏好。菜单打开本身不必取消模式。

**自主散步：** 用户要求后再加入。行走动画必须和桌面位移同步，以可见轮廓限制屏幕边界，并处理鼠标介入、拖动和休息。原地走路循环不是已经实现自主散步的证明。诞诞截至 0.3.2 尚未加入自主平移。

## 响应速度和自然感

先测量用户触发、开始准备、进入目标循环三个时间点，区分排队等待、姿态准备和磁盘解码。首次加载慢时保持窗口和原待机继续响应，在适当线程预热下一段，避免冻结 UI。

若用户觉得响应慢，优先清理未开始的随机队列、选择耗时更短的合法路线和缓存。确需提速时，针对审核过的准备段平滑变速，保留实际动作语义；循环和开场不自动整体快放。源帧跨采样计数可能来自主动提速，不能一律解释为性能卡顿。

若用户觉得“自己玩得太慢”，先调整停留轮数、小动作出现频率和姿态轮换。动作速度、接点处理、随机策略是不同参数。使用多个随机种子检查姿态不会锁死、动作覆盖合理，然后实际观察一段正常速度运行。

## 播放与坐标故障

- 远处转身结束突然放大：检查是否错误复用近处状态与退出路线，先回到同尺度中间态。
- 坐姿歪头突然变瘦：检查整段固定宽高变换及参考，而不是逐帧拉伸。
- 反复互动后裁到耳朵尾巴：检查注册位移累积和缓冲边界；必要时窗口重新居中并反向补偿画面，保持桌面位置。
- 缓存没命中：校验来源、大小、修改指纹或内容哈希；缓存可丢失并回退原资源。派生 idle 安装完成后再运行覆盖统计。
- 无边框透明窗口需要可恢复入口：点击穿透后仍要有托盘或快捷入口，能正常关闭，退出先完成用户认可的离场动画。

## WPF 分支定位

仅在已有 WPF 桌宠上使用：MainWindow.xaml.cs 管状态、SpriteRuntime.cs 管帧。诞诞旧分支修过 LyingDown／CurlingToSleep 的当前帧反放、Waking／Rising／Reacting／Turning 的 Resume，以及 PlayFromFrame 反向终止帧 pending 语义。这些是可定位的历史故障模式，不是要求所有框架使用同名类。
