# 照片、标准姿态与首尾帧的工作流

## 1. 先选默认值，再展开计划

没有额外要求时，用照片中的物种与外貌做写实桌宠；不为图省事改成卡通。优先固定镜头、单只宠物、全身入画、均匀背景。画布和光照作为项目级参数写一次，所有卡片的可复制提示词也要包含它们。

默认可以提出方形画幅、柔和正面光、正面站姿作为中心状态，四周保留动作余量。分辨率和 fps 应根据工具实际支持选择；建议时长与端点稳定时间是目标，验收以实际成片为准。白毛多时不要宣称白底天然好抠；已有白底可走主体分割／剪映透明导出，新生成可选与毛色分离的均匀背景。

照片表至少包含：编号、视角、可确认特征、遮挡／模糊／透视问题、用作身份还是姿态参考。对“另一侧花纹、完整尾巴、标准站姿腿长”没有证据时，标注未知并提出如何补参考。不要把俯拍缩短的腿或广角大头固化成真实比例。

## 2. 分开管理状态基准与视频帧

可用 ID：P 为原照片，I 为新生成标准图，E 为从已通过视频提取的帧，V 为视频，C 为运行时片段。编号是交接协议，不意味着文件已经生成。

示例：`P01/P02 → I-F → V-sit-down → E-sit`。只有 V-sit-down 实际生成并验收后，E-sit 才存在。计划文件必须将这种未来依赖写成“待提取”，不得虚构它已经可用。

每个标准姿态只有一个当前认可的视觉基准：

| 状态 | 首选建立方式 | 何时重新生成静态图 |
| --- | --- | --- |
| F：正面站立 | 多张照片生成 I-F，核对身份与比例 | 初始基准不合格或用户改造型 |
| S：正面坐姿 | F→S 转换的最后稳定合格帧 E-S | 没有能用的尾帧；或需要预览目标姿态 |
| L：抬头趴姿 | S→L 的合格尾帧 E-L | 同上 |
| P：枕爪趴姿 | L→P 的合格尾帧 E-P | 同上 |
| WL/WR：左右侧身站姿 | 从 F 转身的合格尾帧 E-WL/E-WR | 侧身花纹与比例无依据时先补参考，不假称准确 |
| T：专用打字姿态 | 连续打字视频进入段结尾，或专门进入片段尾帧 | 需要单独生成循环、进入视频不可用时 |

新生成坐、趴、侧身图必须同时引用宠物身份照片与当前基准，保持机位体系、体型、地面线和光照；它们可以是目标参考或备用方案，不要求在提取合格尾帧后还再生成一遍。

## 3. 每条动作边都选一种连接策略

| 策略 | 实际上传什么 | 使用场景 | 必查项目 |
| --- | --- | --- | --- |
| 基准图复用 | 当前状态的认可图 | 同姿态呼吸、歪头、舔鼻、叫声 | 尾部回到该基准附近，循环相位连续 |
| 局部尾帧续作 | 前段最后稳定合格帧 | 新姿态、连续转向、道具进入后的下一步 | 前段身份与端点先通过；不得带错肢体继续生成 |
| 首尾图约束 | 当前实际首图 + 已有目标基准图 | 需要回到 F 等既有姿态，且平台支持首尾图 | 保持自然过渡，不能靠淡化变成目标图 |
| 仅首图 + 目标描述 | 当前首图；目标基准若只能附参考则说明角色 | 平台只接受首帧 | 明确目标姿态，生成后对照目标图检查，不假装保证像素一致 |
| 同源拆段 | 一段连续视频 | 打字／步行进入、循环、收尾 | 切点依实际成片确定，保持同一画布与坐标 |
| 补桥接视频 | 现有片段尾帧到下一段基准 | 两段都很好但端点不能直接连接 | 路线自然且确有必要，不默认交叉淡化即可修复 |

选取尾帧时避开运动模糊、眨眼闭眼、抬脚未承重、尾巴截边、道具半消失、结束特效和全透明帧。取“最后稳定合格帧”并记录实际时间戳／帧号；不可预先写一个适用于所有视频的固定尾帧编号。

## 4. 决定分段还是整段

连续视频一次生成的优势是身份、比例和坐标较一致，之后可按进入／循环／退出拆开。诞诞的打字与行走确实采用过这条路线。

出现以下情况优先拆分：模型遗漏转身或收尾；时长不足；动作太多；循环不可控；首尾要接已有标准姿态。分开做左右转身／返回，就是针对缺转身的修正。每拆一段都必须增加明确参考帧和依赖，不能只把长提示词切成几条不相连的文本。

## 5. 不能把所有视频串成一根尾帧链

站姿舔鼻、站姿歪头、站姿叫声都从 F 的同一认可图派生；不要让歪头从舔鼻的任意尾帧开始，再让叫声继承歪头的误差。

不同姿态间的主干可以是 `F → S → L → P`。回程优先 `P → L → S → F` 的自然正向动作。它们的目标分别是原 E-L、E-S、I-F，而不是遇到偏差就修改原姿态定义。左右分支也要回到同一 F，形成闭环。

同名姿态还可能有不同相机尺度、朝向或道具状态，例如远处正面与近处正面、有键盘的站姿与无键盘站姿；它们应有不同状态或明确的道具变化，不能直接当作一个节点。

## 6. 逐批推进与返工

第一批先做 I-F、F 待机、F→S、S 待机、S→F；确认角色和连接方法后，再做趴姿、侧身与互动。完整规划先交付，实际不一次生成几十条。

每个文件状态：计划中 → 已生成待验收 → 通过／返工。只有通过的文件可被下游引用。没有真实图片时仍可把计划和提示词写全，但要明确“先运行这一张，后续等待合格参考”，不假造测试结果。

失败时按原因处理：

- 身份、腿长、花纹错误：退回标准图，先修角色；不要用有错误的尾帧继续扩散。
- 当前段运动缺失：减动作、拆段、补明确承重过程，重新生成当前段。
- 动作好但尾帧无法接基准：选择重做收尾、首尾图约束或补桥接；不得把已有依赖全改名来掩盖断裂。
- 尾帧基准确需替换：版本化基准并列出受影响子树，只重做依赖这个版本的动作。
- 工具不支持所需首尾输入：改用已说明的回退方式，不编造按钮、参数或成功保证。

默认每段先做一个候选，明显失败时至多两次有针对性的提示词修正；仍失败就报告缺口、改分段或暂停该分支。新的付费生成和额外花费按当次授权执行，不让重试无限增长。

## 7. 最后交给处理和程序阶段什么

交接清单包含原视频、alpha 素材或透明帧、实际 fps/分辨率/帧数、首尾状态、基准图版本、取帧位置、同源拆段范围、循环方式、方向、道具、已知缺陷和被替代旧版本。

MOV 要实际检查透明通道；剪映智能抠像导出带 alpha MOV 后再抽帧，是本案例落地过的方式。30 fps 与 60 fps 都需要说明真实采样来源，不能靠导出设置声称运动细节增加。程序中保留同姿态尺寸、脚底和同源坐标，完成互动取消与正常退出，再打包验证。
