# 发布与验证

## 先明确交付形态

沿用工程技术栈。已有 WPF 可发布自包含单 EXE；已有 PySide6 常适合包含 EXE、运行库和素材的免安装目录，再压成 ZIP。不要为了“只有一个文件”强制将大批素材塞入每次启动都要解压的自解包程序。

确认目标 Windows 版本与架构。能在开发机隔离环境运行，只证明该范围；未经测试的其他电脑、Windows 版本、DPI、多屏热插拔和休眠恢复不能列作已通过。

## 运行素材和存储

制作源 MOV、透明 PNG、运行数组与可重建缓存分层保存。打包不应重新生成、压低质量或删减用户已经确认的动作。透明空白裁切若用于无损存储，要验证贴回原画布后逐像素一致。

发布前核查配置中的每个来源与派生片段：

- 资源路径包内相对，解析到发布根目录，不依赖个人 Desktop、开发路径或固定 D 盘缓存。
- 来源数组全部存在，实际读取数组头部，检查 shape、dtype、通道顺序及透明约定。
- frame_start、frame_count、hold_index 和 crop_rect 均在资源边界内。
- 派生循环或端点停留可以复用同一来源，不把派生数量冒充新视频数量。
- 可选的快速缓存失败、损坏或空间不足时能回退；不可把构建机现成缓存当成必带依赖。

预乘 alpha 与 straight alpha 要与渲染接口一致；不要仅凭透明像素有 RGB 值就判断损坏。全透明的退出末帧可合法存在。必要时验证贴边、主体为空、预乘颜色超限及首尾几何；阈值根据角色和实际显示尺寸确定，历史像素阈值不通用。

## 打包与启动故障

PyInstaller 等打包器应在明确的构建环境中运行，核查 PATH 带入的同名 DLL；QtCore 导入失败时先看实际收集来源、导入／导出及成功环境加载了什么，不要盲目替换 VC 库。

诞诞曾误收 Poppler 的 ICU DLL，导致 Qt 期望的符号缺失；经证据确认后，排除误采库并使用目标系统 ICU 才解决。这个修复不适用于所有 Qt 包：不同 Qt／系统版本先检查，不能全局写死排除某 DLL，更不要直接打包系统目录中的全部 DLL。

核查 Python 运行库、QtCore／Gui／Widgets、平台插件、图片插件和实际依赖。对 GUI 入口检查无常驻终端，异常可读，日志有限额；添加图标时检查最终 EXE 中的图标资源，不能只确认旁边有 PNG。

WPF 旧分支已使用过的发布形式（将路径替换为实际工程）：

```powershell
dotnet publish .\work\DogDesktopPet\DogDesktopPet.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true --nologo
```

若程序提供 `--smoke-test`，执行它并从仅含最终 EXE 的独立目录复测。没有该参数的工程不要假设存在。

## 三类证据分别保留

| 检查 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 资产、状态、队列与加速诊断 | 索引、路径、指定动作覆盖、取消和返回逻辑 | 正常速度流畅度与实际性能 |
| 正常时钟、可见窗口的实际运行 | 测到的路线、帧调度、响应和资源占用 | 未运行的其他硬件与长期稳定性 |
| 最终 ZIP 真解压后启动 | 交付包的依赖和当前目标环境首开 | 全新系统或收件人电脑兼容性 |

状态／互动修改只跑相关回归；发布涉及全部资源时再完成全动作覆盖。完整覆盖运行用固定队列，避免随机模式和用户输入改变路线。记录所用 EXE／配置身份、开始与结束、动作来源覆盖、错误、帧跳过口径、真实或推进时钟。

正常速度测试记录触发到准备、触发到目标的时间；资源记录采样时段和 CPU 口径。单逻辑核心百分比不是整机百分比；未测 GPU 就不写显卡负载。不要用“窗口刷新 60 Hz”证明源素材或实际渲染是 60 fps。

## 最后一个 ZIP 也必须实测

1. 冻结候选目录并记录版本、配置和 EXE 哈希。测试后如果又修改二进制或资源，相关结论需重验。
2. 生成完整 ZIP，区分完整包与补丁；说明是否需要旧版。避免把打包输出放进待打包目录。
3. 解压到一个新的、含空格或中文的路径，逐文件比对载荷 SHA-256。清单本身不是缺失的载荷文件。
4. 在该解压位置运行最终程序，隔离开发用 PYTHONPATH、Python PATH 与工作目录；使用新的测试数据目录，避免破坏用户设置。单实例存在时先判断是否老进程拦截新启动，不把“马上退出”直接当作启动成功。
5. 确认窗口、透明与置顶、代表动作、交互入口、无终端、正常退出，并按变更范围补相关覆盖。只关闭本次测试实例，不强杀用户正在用的桌宠。
6. 校验正常输出与交付副本一致，再报告结果。发送给别人时需要整个 ZIP，保留 `_internal` 等伴随目录；只有真正单文件发布物才可单发 EXE。

最终说明包含版本、完整包／补丁身份、解压后入口、验证范围和仍存在的源素材限制。无需在产品按钮和日常用户流程里暴露缓存、数组或 DLL 等实现细节。
