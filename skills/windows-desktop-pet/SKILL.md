# 从宠物照片到桌宠

用户给几张宠物照片时，主动规划整套制作流程。目标是让另一个人照着顺序操作，知道每一步上传哪张图、粘贴哪条提示词、保存什么、交给下一步什么。不要把任务误解为必须一次自动生成全部视频或程序。

## 使用边界与默认工作方式

- 先读本文件和下列三个规划参考，再根据照片输出项目专属方案；不能只给泛泛建议或让用户自己列动作。
- 未指定时，以与照片一致的写实角色、Windows、同一个固定机位体系、站坐趴与自然陪伴为默认。狗、猫等按物种调整叫声、肢体和习惯，不能套用不适合的解剖动作。
- 照片只证明能看见的特征。缺全身、背面或另一侧时明确未知，给补充参考方案；先推进可确定部分。不要把生成补全的花纹说成真实特征。
- 没有指定生成平台时给平台无关提示词，并分别说明仅支持首帧、支持首尾帧时怎么用。不宣称某工具支持未核实的能力。
- 此次只授权规划时就交付规划，不自动付费生成、调用外部账户或发布。用户要求制作时，在可用工具和授权范围内逐批执行；没有视频工具时交付可复制提示词并接收用户返回的素材。

## 第一步：照片与角色基准

给照片编号 P01、P02……并实际查看。提取面部、耳形、鼻色、眼部、躯干花纹、腿长、尾巴和可见左右差异，区分事实与未确认部分。选身份主参考，记录其他照片补充哪一部分；不要混入照片背景、人物或家具。

先设计标准正面站姿图 I-F；通过后才扩展姿态。头部近照不能直接当成全身动画首帧。画幅、地面线、全身余量和光照属于本项目统一参数，静态图、视频提示词和验收都要引用同一组参数。

## 第二步：动作图与生产计划

阅读 [规划与首尾帧规则](references/planning-workflow.md) 和 [动作库与顺序](references/action-library.md)。先设计基础闭环，再加入日常变化、拖动、摸头、键盘和出入场。

为每个选中动作记录：动作 ID、起止姿态、用途与阶段、首帧具体来源、目标尾姿态／尾帧、循环或拆段方式、依赖、执行顺序、实际输出文件和失败处理。每个持续互动都要有进入、循环、退出；不能让某个姿态没有返回或离场路线。

**规划阶段一次给全所选范围的清单与提示词；实际生成按小批次验收。** 不能先只给三条提示词，然后要求用户不断追问才能拿到完整计划。已选中的扩展动作也要有明确卡片；被延后的功能标明未纳入本轮。

## 第三步：配对提示词与交接

按 [提示词卡与输出格式](references/prompt-cards.md) 给每个动作写完整卡片。至少写清静态提示词（或复用哪张已有图）、动态提示词、输入图片对应关系、尾帧处理和下一步。

最重要的决策：

- 同一姿态的小动作统一从已认可的基准图出发，避免全局“一条视频尾帧接下一条”导致角色逐步漂移。
- 新姿态可以由上一个转换动作的**最后稳定合格帧**建立；不要无条件取视频物理最后一帧。
- 已有合格实取尾帧能作参考时就复用，静态生成提示词保留为备用，不为每个动作重复造一张图。
- 需要回到已有姿态时，保持该姿态的原基准；坏尾帧不能冒充原基准。选择返工、补过渡或局部重做依赖，而不是硬切。
- 连续视频可拆进入／循环／退出；若长提示词总漏动作，拆成明确段落分别生成。不能强制所有素材都按一种拆法。
- 倒放只作为经过观看确认的备选。起身、踩地、眨眼和道具收放优先制作自然正向返回，不把倒放自动称为同等自然。

给出的可复制提示词必须展开本宠物特征、起止姿态、机位及背景；不能留下“同上”“自行补充”或未填变量。允许在可读的总规范里集中说明规则，但实际复制块要能独立使用。针对摸头允许人手、针对键盘允许道具，避免负面词与动作本身互相矛盾。

## 第四步：接收成片并继续

每收到一批，回填状态为待生成／待验收／通过／返工，并记录实际参考帧和文件名。检查身份、完整肢体、运动、尺度、脚底、首尾衔接和循环；通过才解锁依赖。参考帧若改变，列出受影响的下游卡片。

实际透明处理读 [素材流程](references/asset-pipeline.md)；接入程序读 [播放器与互动](references/runtime-and-interaction.md)；交付读 [发布与验证](references/release-and-verification.md)。这些是后续阶段，不能取代前面的照片到提示词规划。

完整验收至少走一遍基础姿态往返、所选互动的开始／取消／恢复／退出，以及最终解压程序启动。规划通过、素材通过、程序通过分别报告。

## 必须交付的可读结果

1. 照片与角色特征表、已选默认值、缺失视角。
2. 标准图清单：哪些新生成、哪些由已验收尾帧提取。
3. 动作总表与完整首尾姿态图。
4. 每个所选动作的静态／动态配对卡。
5. 可执行的生成顺序与交接表，包括首次应执行的那一步。
6. 逐批验收、失败回退、透明导出与程序交接说明。

输出太长时保存为几份相互链接的 Markdown，并在回复中给路径。不要用缺少提示词的摘要代替实际交付。

## 复现依据

[诞诞的已验证做法](references/verified-dandan-workflow.md) 区分实际运行证据与本技能新增的规划约束。复现的是制作方法和工作顺序，不承诺生成模型每次产出相同画面。通用动作图检查脚本位于 `scripts/audit_action_graph.py`；其通过不等于视频或成品通过。
