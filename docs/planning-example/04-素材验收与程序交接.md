# 素材验收与程序交接

[角色与标准图](01-角色与标准图.md) · [完整动作卡](02-动作与完整提示词.md) · [逐批顺序](03-生成顺序与交接.md)

本文件是视频返回后的执行说明。当前尚无新视频，不能报告素材或程序已通过。这里不要求使用者在生成平台完成程序开发。

## 先验收源视频

每批先完整正常速度观看，再检查首、中、尾和接点。身份以 P01 和已认可 I-F 核对；坐、趴、侧面按各自原基准比较，不强迫不同姿态等高。

- 身份：脸部白纹、鼻色、耳形、眼部、胸毛范围、已有侧面花纹和尾巴造型一致；不把模型补全说成照片已证实。
- 解剖：四肢、耳、尾尖完整，支撑脚合理；起身、坐下、趴下有自然承重；不出现额外爪、穿模或瞬间换腿。
- 几何：机位、焦距、身体大小和源画布保持一致；脚底不漂，躯干不因逐帧自动裁切而缩放。
- 循环：至少连续观看三轮，检查首尾位置、运动方向和速度；步态还要是同一落地相位。不能仅凭两张静态图相似判循环通过。
- 接缝：逐条看动作图全部边；返回段确实到原 I-F/E-S/E-L/E-WL。坏尾帧不升级成新基准。
- 片段：行走进入、循环、收步和回正面分开登记；GL 是运动相位，不能冒充 WL 静止站姿。

只有看过真实视频才能填写“通过”。动作图检查器通过只证明声明的结构，不能证明视频自然、循环顺或程序已工作。

## 选定的透明处理路线

默认将原生灰底视频交回，由后续素材处理者做主体分割和毛发边缘修整，再导出带 alpha 的无损 PNG 帧序列及预览。这样使用者本轮只需生成和下载原片。

如果使用者已经掌握且当前软件实际支持“智能抠像 → 带 alpha 的 MOV”，可把透明 MOV 和未抠原片一起交回；它是可选交接方式，不假设所有版本都有相同按钮。MOV 容器名称本身不证明透明。

处理顺序：先拿 A01、A02、A04 和一条侧面片段做代表性试处理 → 检查白毛和轮廓 → 再批量。不能先把所有片段抠完才发现白胸被删。

1. 保留原片，读取真实分辨率、原生 fps、帧数和编码。重复帧、插值帧与真实采样分开记录。
2. 用主体分割保留白口鼻、白胸和细毛；不要按白色阈值删除。中性灰仍可能贴近某些毛色，发现轮廓漏失就修分割，不许声称均匀背景必然好抠。
3. 用棋盘格、深背景、浅背景各预览；检查鼻部、耳缘、白胸、脚趾、尾尖是否有缺口、灰边或透明闪烁。
4. 实际解码 RGBA，确认 alpha 同时含主体和透明背景。PNG 序列应有连续帧号；另附播放 fps，PNG 自身没有整段 fps。
5. 每段使用固定画布与注册变换；不要逐帧按包围框归一化。站坐趴的自然高度不同，统一地面，不统一头顶高度。
6. 同源行走切段保留原坐标和实际帧区间。若裁掉透明空白节省存储，保留原画布尺寸、裁切矩形与贴回偏移，并验证恢复结果一致。

无损 PNG 命名示例：`frames/A02/frame_000000.png`。这只是未来计划命名，不表示文件已存在。透明素材的通道与 alpha 约定必须与播放器匹配。

## 交给程序开发者的内容

交付原视频、通过的基准图、透明帧或真实 alpha MOV、深浅背景预览、实际动作清单和交接表。每条记录：动作 ID、版本、来源视频、起止状态、实际 fps/分辨率/帧数、取帧位置、片段区间、方向、脚底锚点、循环方式、已知缺陷、替代的旧版。资源使用包内相对位置。

程序从 F 开始。状态必须匹配动作起点，动作结束才更新状态。持续待机在可衔接的基准相位离开，不能把任意呼吸或抬脚帧硬切到转换首图。

建议本轮最小菜单只包含：站立、坐下、趴下、枕爪、退出；保留可找到的恢复／退出入口。姿态指令覆盖未开始的旧指令，重复目标合并；不添加随机动作队列。

## 左拖的明确行为选择

以下是为本轮选定的交互规则，尚未实际测量响应速度。画面左指屏幕 x 方向减小；程序跟随鼠标移动窗口，源视频只做原地步态。鼠标抓取偏移始终保留，不因透明缓冲或姿态变化让小狗跳到另一位置。

| 触发时真实状态 | 应执行的合法动作 | 松开或取消时 |
| --- | --- | --- |
| F | W01→W02E→W02L | 尚未起步则取消未开始动作；已到 WL 则 W03R |
| S | A04→W01→W02E→W02L | 当前短转换完成到合法端点，取消未开始走路 |
| L | A10→A04→W01→W02E→W02L | 当前短转换完成，取消后续走路，不瞬间站立 |
| P | A09→A10→A04→W01→W02E→W02L | 当前短转换完成，取消后续走路 |
| W01 正在转左 | 完成当前转向到 WL | 接 W03R 回 F，不开始 W02E |
| W02E 正在进入步态 | 到已认可 GL 端点 | 接 W03S→W03R；取消循环目标 |
| W02L 正在循环 | 持续左拖时继续循环 | 正向前进到下一个约定 GL 接点，再 W03S→W03R；不重播整轮作为强制收尾 |
| W03S 正在收步 | 完成至 WL | 持续取消就 W03R；重新左拖则从 WL 接 W02E |
| W03R 正在回正面 | 完成至 F | 若重新左拖仍有效，再从 F 开始 W01 |

小幅鼠标抖动不反复进退；方向阈值与滞回以实际显示尺寸测试后定值。第一版单 GL 退出接点最多可能等待一个步态周期；必须实测等待时间与观感，觉得迟缓再补其他相位的收步素材或缩短合法路线。

本轮没有右走素材。向右或主要竖向拖动仍可搬动窗口；若正处左走，则取消左走目标，按 GL→WL→F 收尾，之后保持合法姿态随鼠标搬动。不镜像左走冒充真实右侧。准备姿态时窗口也应继续跟手，不能等全部动画播完才移动。

若使用暂停来等拖动阈值，所有接管分支必须恢复动画。退出命令及时停止未开始任务，允许正常关闭，不为本轮未制作的离场动画等待。

## 程序验收路线

素材通过后再接程序，正常速度实际观察以下情况：

1. F→S→L→P→L→S→F；四种待机分别连续循环。
2. F→WL→GL→至少两轮左走→WL→F；源步态与窗口位移方向一致，耳尾不被窗口裁切。
3. 从 S、L、P 开始左拖；分别在姿态准备、转向、进入步态、循环、收步、回正面时松开，再恢复左拖。
4. 左走中改为向右或竖向搬动；不突然翻面，不保留已取消的旧目标。
5. 重复姿态指令、快速变更姿态、按住未越过阈值、快速点击拖放；无锁死、永久暂停或队列积压。
6. 每种姿态与拖动阶段正常退出，托盘或菜单仍能操作。记录触发、开始准备、进入目标三个时间点，不能只凭感觉声称响应快。

## 最终 Windows 交付门槛

本轮规划不选框架，也不承诺现成 EXE。收到素材后根据实际工程沿用技术栈，再确认目标 Windows 版本和架构。候选包必须包含全部运行依赖；只有真实单文件发布物才可单发 EXE，多文件版应完整压成 ZIP。

发布前检查全部资源路径为包内相对位置，索引不越界，透明约定一致；在正常速度可见窗口中跑上述路线。然后将最终 ZIP 真正解压到新文件夹，核对载荷哈希，在该解压位置启动并确认透明、置顶、交互、退出与无常驻终端。测试后若改二进制或资源，重验受影响部分。只关闭本次测试实例。

结论分开记录：规划是否齐全；源视频／透明素材哪些通过；程序哪些路线通过；最终包在哪个实际环境首开通过。没有测试的其他电脑、DPI、多屏或休眠恢复不能写成通过。

## 后续计划

| 后续功能 | 加入前需要补齐 |
| --- | --- |
| 右侧拖动走路 | 真实右侧花纹参考、独立转向、步态进入／循环／收步／回正面；不默认镜像 |
| 站坐趴小动作 | 各姿态从原基准派生，做完回原基准；不串成长尾帧链 |

| 鼠标注视 | 同一身份的方向锚点和合法进出，不频繁切换不一致轮廓 |
| 自主散步与随机模式 | 桌面位移、步态、边界和人工介入同步；本轮原地走路并不代表已实现自主移动 |
| 动画出入场 | 隐藏状态、完整出场与离场，以及从各姿态回到离场入口的路线 |

后续功能尚未纳入本轮生成清单；确定加入时再写完整配对卡并逐批制作。
