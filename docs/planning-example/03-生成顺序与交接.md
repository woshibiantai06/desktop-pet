# 生成顺序与交接

[角色与标准图](01-角色与标准图.md) · [完整动作卡](02-动作与完整提示词.md) · [后续素材与程序](04-素材验收与程序交接.md)

第一次实际操作：打开图片生成功能，上传 P01、P03、P02，按第一份文档的 I-F 卡制作一张正面全身站姿草稿。当前没有合格 I-F，先不要做视频。

## 每段都这样操作

1. 找本表的前置状态，确认输入图是实际通过的版本。将本卡的首图上传到真正的首帧槽，复制第二份文档对应的完整提示词。
2. 有真实目标尾图且平台支持首尾帧时，再放尾图。仅支持首帧时使用同一正文，生成后旁看目标图核对，不认为文字能保证像素完全一致。
3. 先生成一个候选，下载原始质量文件。按计划名保存，真实容器不同时保留真实扩展名。
4. 回传这一批原片、实际参考图版本和简短问题。没有视频时不填“通过”。协作者需要看完整动作，并检查首、中、尾与接缝。
5. 需要建立 E 帧时，只从已通过视频取最后稳定合格帧；走路的 E-GL 取可重复运动相位。记录实际时间戳／帧号，不预定统一帧号。
6. 确认通过才解锁下游。明显失败先定位原因，最多做两次有针对性的提示词修正，再改分段、补参考或暂停分支；不要无限重试。

## 如何回传

每次上传本批原视频和本批实际用的首图；有目标尾图也上传。无需重新上传所有已认可照片。画质压缩预览可以帮助讨论，但透明处理要收到原始质量文件。

建议同时发送下面这张登记表。空项先写“待测”或“待提取”，不要猜数。

| 字段 | 填写内容 |
| --- | --- |
| 动作 ID、版本、真实文件名 | 例如 A02、v1、V-A02_v1.mp4 |
| 当前状态 | 待生成／已生成待验收／通过／返工 |
| 首图与身份参考 | 实际文件版本；P01 是否在身份参考槽 |
| 尾图约束 | 实际上传尾图，或“仅首帧，目标为 I-F_v1” |
| 实测媒体信息 | 宽、高、原生 fps、时长、解码帧数、编码、是否有 alpha |
| 真实取帧 | 来源视频版本、时间戳、帧号、是否采用从零开始的编号 |
| 运行片段 | 进入、循环、退出的实际起止帧；未检查前填待测 |
| 缺陷与判断 | 脸、耳、脚、尾巴、脚底、尺度、接缝、运动各有什么问题 |
| 下游解锁 | 具体允许开始的动作 ID；未通过时写“无” |

实际取帧时保留当前视频完整画布，不为每张基准重新紧裁主体。视频物理最后一帧如果闭眼、模糊、抬脚、尾巴截边或开始特效，应往前找到最后合格稳定帧；不合格就返工。

## 失败回退和版本影响

| 原因 | 当前处理 | 必须等待或重验的下游 |
| --- | --- | --- |
| I-F 脸、腿长、尾巴或造型不合 | 修 I-F，升级版本并重新确认 | 全部依赖 I-F 的动作，包括通过转换产生的 E-S/E-L/E-P/E-WL/E-GL |
| A02 坐姿尾帧不合 | 重做 A02；不建立 E-S | A03/A04/A05/A06/A07/A08/A09/A10 |
| E-S 确实需要替换 | 升级 E-S；重验上游 A02 是否到达它 | A03/A04/A05 及其 E-L、E-P 下游 |
| A05 或 E-L 不合 | 修 A05；不扩散坏尾帧 | A06/A07/A10，以及 A08/A09 |
| A07 或 E-P 不合 | 修 A07 | A08/A09 |
| W01 或 E-WL 不合 | 补侧面参考或重做转身 | W02E/W02L/W03S/W03R |
| W02E 或 E-GL 不合 | 改进入片段或选择更适合的实际相位，记录版本 | W02L/W03S；重验进入与退出接缝 |
| 返回段动作好但尾接不上 | 先用原目标尾图重做收尾；必要时补一条真实桥接，重新登记路线 | 相关接缝；无需把原目标基准改成错误尾图 |
| 单段动作太长而遗漏动作 | 先缩小本段动作；必要时拆成有真实中间帧的两段并登记新 ID | 新中间帧及其直接下游 |

备用静态目标图只能辅助到达原计划姿态，不能替代转换过程。所有基准替换都要把“旧版→新版、受影响 ID、重验结果”写进交接表。
