交付入口：[01-角色与标准图](01-角色与标准图.md)。另有 [02-动作与完整提示词](02-动作与完整提示词.md)、[03-生成顺序与交接](03-生成顺序与交接.md)、[04-素材验收与程序交接](04-素材验收与程序交接.md)。正文使用 P01/P02/P03，未附原照片、原始文件名、个人信息或绝对本地路径。

本轮涵盖 10 条站／坐／趴／枕爪待机及转换，加 5 条左拖进入／循环／收步／回正面视频卡；延期功能只有后续清单，没有扩大本轮生成范围。每条有实际输入、静态复用或备用卡、完整动态正文、输出、取帧、依赖、验收、失败回退和下一步。

## Skill 没有替我直接决定的地方

| 点 | 试用时的处理 | 判断 |
| --- | --- | --- |
| 最初动作库把稳定侧站与行走循环都标成 WL，容易让人把站稳首图接到任意抬脚帧 | 计划先独立使用 WL 侧站、GL 步态相位，并拆出进入／收步。随后重读更新版动作库，已明确 WL/WR 与 GL/GR 及进入、循环、收步边 | 原有实质歧义已由更新解决；本计划与更新版一致 |
| 只要求左拖时，右向／竖向移动怎么做没有唯一默认 | 选择窗口仍可随鼠标搬动，左走自然收尾，不镜像出右走。该选择在程序交接中显式写出 | 正常的产品设计选择，不妨碍完成规划 |
| “各姿态有离场路线”与本轮把动画出入场延期之间需要区分 | 所有姿态能返回 F，正常关闭始终可用；本轮不新造离场动画 | 建议 Skill 明说：关闭能力必须保留，动画离场随范围选择；当前可按用户范围合理处理 |
| 图片／视频平台未指定，不能推断参考槽、首尾图或 alpha 导出按钮 | 写出仅首帧和首尾帧两套输入法；I-F 另给单图参考版；默认回传原视频，后续再做主体分割 | Skill 对能力边界的提醒足够，实际按钮只能在平台已知后补 |
| 待机循环在任意时刻取消，究竟等待哪一个帧点 | 指定离开已认可基准相位；GL 单相位收步可能等待至下一次该相位，并要求实际测响应 | 需要真实视频后才能量化，当前不能伪造帧号或响应数据 |

没有遇到使本轮完整规划无法交付的剩余缺口。缺全身站姿、完整尾巴和可靠侧面是输入照片本身的限制，已按 Skill 区分确认特征与暂定补全；不能靠多写提示词把它变成真实证据。
